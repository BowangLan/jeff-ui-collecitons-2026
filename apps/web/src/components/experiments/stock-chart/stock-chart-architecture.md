# Stock Chart experiment architecture

Run `cd apps/web && bun run dev` and open `/experiments/stock-chart`. The experiment includes 10,010 stock summaries, simulated live quotes, and a slow price-history API. Vite dev and preview serve the API using the local SQLite file at `apps/web/.cache/stock-chart.sqlite`.

## Rendering

- **Load the experiment on route entry.** The collection can read the route metadata eagerly, while `React.lazy` defers the Stock Chart UI and Zustand store until the experiment opens. [Route entry](../stock-chart.tsx)
- **Limit mounted rows with virtual scrolling.** `StockList` keeps `search` and `savedOnly` local and memoizes matches against `stocks[].symbol`, `stocks[].name`, and `stocks[].sector`. `StockResults` uses its local `firstVisible` and `viewportHeight` to calculate the mounted range. It gives the full list its calculated scroll height, then mounts the visible rows and a small buffer above and below. The row identified by local `focusedSymbol` stays mounted so scrolling preserves keyboard focus.
- **Subscribe to what each component renders.** A memoized `StockRow` selects a boolean derived from `selectedSymbol === stock.symbol`. Switching stocks changes that boolean only for the previous and next symbols. The watchlist and detail header use the same `BookmarkButton`, and both select `bookmarksBySymbol[symbol].value` for their symbol. The Bookmarked filter uses shallow equality on the resulting stock references, so a save acknowledgment preserves the list when membership stays the same. The detail header looks up the selected quote through `stocksBySymbol[selectedSymbol]`.
- **Isolate chart interaction in its own Zustand store.** `usePriceHistory.chart.preset` determines the visible slice of the history already in memory. `usePriceHistory.chart.cursorIndex` drives the plot cursor and readout. The chart subscribes to the preset separately from cursor and selection changes. The memoized `PriceSeries` keeps its SVG geometry during a drag. [Chart](price-history.tsx) · [Chart interaction store](price-history-store.ts)

## Chart range selection

1. **Start on the plot and track on the document.** The plot's bounding box converts `event.clientX` to a clamped index in the visible history. A primary press stores that index in `usePriceHistory.chart.drag.anchor` and records `chart.drag.pointerId`. Pointer capture helps route events. Document listeners keep the gesture active if capture is lost or the pointer leaves the plot. Each store action checks `chart.id` and `chart.preset` so events from an old chart or preset cannot update the current one.
2. **Buffer raw input before rendering.** The hook's `pending.current` ref holds the latest X and the minimum and maximum X since the last frame. One animation-frame callback publishes `chart.cursorIndex` and, once the pointer has crossed a visible session, `chart.drag.preview`. Keeping both extremes recognizes a drag that crosses a session and returns to its anchor before the next frame. [Pointer handlers](history-plot-controls.ts)
3. **Render one effective range.** The highlight, date label, and low, high, and session count use `chart.drag?.preview ?? chart.selection`. Both values are pairs of indices into the visible history. The chart sorts the endpoints so either drag direction works and includes both endpoint sessions in the stats. The store writes `chart.selection` and clears `chart.drag` in one update. When the release and preview endpoints match, the highlight and stats stay the same through that handoff. [Chart rendering](price-history.tsx) · [Selection transitions](price-history-store.ts)

How the chart chooses the final endpoint depends on which signal arrives:

| Signal                                                                                             | Result                                                                                                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pointerup`                                                                                        | Commit the session under the release position. This also handles a release that lands beyond the last preview or arrives before the first preview frame.                                                                                              |
| A move from `chart.drag.pointerId` with `event.buttons === 0`                                      | Schedule a release fallback for the next animation frame. A real `pointerup` or another move with a button held cancels that fallback. If the fallback runs, it uses the position of the buttonless move.                                             |
| `pointercancel`, window blur, or a new press from the same pointer before the old gesture finished | Preserve `chart.drag.preview` as `chart.selection` if a preview exists. Otherwise keep the previous `chart.selection`.                                                                                                                                |
| A tap or click                                                                                     | A tap inside the painted highlight keeps the selection. A tap outside it, including a click elsewhere on the page, clears it. The outside-click listener remembers where the pointer went down so it can distinguish a drag release outside the plot. |

Run `bun test apps/web/tests/stock-chart-range-selection.test.ts` from the repo root to exercise the store transitions for rapid replacements, interrupted previews, and outside clicks. Browser checks cover the ordering of pointer events, including a buttonless move followed by `pointerup` and a drag that continues after capture loss. [Regression tests](../../../../tests/stock-chart-range-selection.test.ts)

## Data fetching

- **Split summaries from histories.** `GET /api/stock-chart/stocks` returns the catalog in one request. SQL derives `stocks[].price` and `stocks[].changePercent` from the latest two saved `stock_prices.close` values for each symbol. `GET /api/stock-chart/stocks/:symbol` returns 100–1,000 entries with `points[].date` and `points[].close` for just that symbol after a simulated delay of 1–3 seconds. Synthetic stocks start with two stored closes. The detail API generates and persists the remaining closes on first request.
- **Cancel stale work and bound the cache.** Changing symbols aborts the previous fetch. The server cancels its pending delay if the client disconnects, and the store accepts a result only from the current request controller. Successful responses populate `detailsBySymbol[symbol].points`. The store holds up to 32 histories and evicts the oldest fetched entry when full. A cached selection renders immediately, and **Reload history** bypasses the cache. [API and SQLite schema](../../../../server/stock-chart-api.ts) · [Zustand store](store.ts)

## Live quotes

- **Batch the entire catalog.** `GET /api/stock-chart/quotes` sends one server-sent event per second. Each event carries integer cents in `pricesInCents`, indexed by the catalog response's `stocks[].quoteIndex`. The client checks `catalogVersion` and the array length before applying a tick. One server timer generates and serializes each full snapshot for every connected client. A slow connection can skip a tick and catch up on the next snapshot without replaying updates. [Quote feed](../../../../server/stock-quote-feed.ts)
- **Render quotes independently.** A dedicated Zustand store replaces `pricesInCents` once per tick. Each mounted price display subscribes to just `pricesInCents[stock.quoteIndex]`, so a row that scrolls into view reads the latest price immediately. The displayed percentage change is derived from the live price and the summary's `stock.previousClose`. Live ticks update the watchlist and detail header without changing `detailsBySymbol[symbol].points` or `bookmarksBySymbol`. [Quote store](live-quotes.ts)
- **Keep the most recent price during reconnects.** The browser's `EventSource` reconnects automatically after a dropped connection. The feed's `status` reports the connection state while the price displays keep their last accepted snapshot. Opening or leaving the experiment starts or closes the stream. Simulated live prices are held in memory. The database stores the closes in `stock_prices.close`.
- **Pause the stream from the header.** The switch controls `QuoteFeedStatus.enabled`, which defaults to on when the experiment opens. Turning it off closes the `EventSource` and holds the last `useLiveQuotes.pricesInCents` snapshot. Turning it back on starts a new connection and keeps that snapshot visible until the next valid frame for the same `catalogVersion`.

## Immediate UI feedback

- **Publish the loading state synchronously.** The store sets `selectedSymbol` and `detailStatus` together before starting an uncached request. The header can show the summary from `stocksBySymbol[selectedSymbol]` while the chart shows a loading state in the same panel. Failed requests show a retry action. The footer's request time comes from `detailsBySymbol[symbol].requestMs`, measured on the client through response parsing.
- **Bookmarks update optimistically.** A click changes `bookmarksBySymbol[symbol].value` before the API call and sets `bookmarksBySymbol[symbol].saving` to mark the active writer. Later clicks update `.value` while that writer is active. After each response, the writer compares the response's `bookmarked` field with the latest `.value` and sends another write only if they differ. The response reflects whether SQLite has a matching `stock_bookmarks.symbol` row. When the writer finishes, it reconciles the optimistic value with the last acknowledgment. If a write fails, that reconciliation rolls back the UI and sets `bookmarkError`. [Selection and bookmark actions](store.ts)

The catalog uses client-side search and virtual scrolling. The initial transfer grows with the number of summaries, while the number of mounted rows depends on the viewport height and the scroll buffer. The history cache lives for the current page session, and SQLite persists one shared bookmark list across reloads.
